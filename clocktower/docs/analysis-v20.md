# v0.20 分析流程、夜序与确定性

## 流程

1. 本地固定本次证据快照，整理人数名额、条件数字联立、公开触发、死亡/复活时间线及本剧本夜序。这些准备不调用LLM、不打印过程。
2. 立即打开本次报告，按用户选择的模型和思考模式发起一次流式分析；模型在内部核验前提、配额、时间线与候选后输出短报告，不打印计划或思维过程。
3. 普通路径一次调用完成，不固定增加“先理解剧本”等准备轮。仅默认新分析检测到具体关键矛盾或信息充分时遗漏座位候选，最多追加一次核对；不再因字数较多而追加调用。核对期间保留已显示初稿并显示核对状态，修订完成后整体更新，避免两份文字交替流式覆盖。核对中断保留初稿并明确未完成。
4. 关闭报告可继续记线索。后台完成时不抢回焦点；报告保存在历史，已有阅读位置与未提交草稿保留。停止、错误和断流仍保留已收到的内容。

独立分析继续只带最新本局资料；追问沿选定对话补入变化。历史报告不当证据，旧快照不重写。普通与深度资料附加范围继续分离。

## 报告

- 顶部“确定与优先前提”：用【确定】和【不可能】标识已知事实或满足全部有效机制检查的结论；不能将普通声明或某分支中的必然结论升级为共用确定身份。
- 【高概率】为有具体依据的优先假设，仍可推翻，不是硬排除；不给无依据的百分比。夜死的常见善良倾向与本人已知角色认证分开。
- 每个“可能A/B/C”内部按号码覆盖所有座位，包括死者。共用确定身份可沿用，相同候选范围可合并为号码组/范围和剩余角色池，附类型配额及必要的相互约束；个体候选的并集不代表可以任取组合。
- 信息很少时未知座位打包，不强造复杂分支；信息较多时省重复推演，不省必要条件。最后只给本人当前可执行的行动与尚未记录的具体问题。

## 夜晚参考

来源：[钟楼百科·夜晚行动顺序一览](https://wiki.biligame.com/bloodontheclocktower/夜晚行动顺序一览)，2026-11-12读取。

该页明确说明部分顺序是对原表的优化，也允许使用原顺序。保存首夜85项、其他夜晚121项的角色索引，仅将本剧本匹配版本的角色顺序送入分析，不复制说书人布置/唤醒操作。剧本信息中可展开本局夜序并访问原页。

- 不能只按红方/蓝方排顺序。标准暗流中投毒者、僧侣在小恶魔前；占卜师、共情者等常规信息在击杀后，间谍看魔典又更晚。
- 普通能力在死亡时停止，并非统一到下一夜才停止。夜初存活不等于已经行动；夜里被小恶魔杀死的真占卜师来不及获取当夜的常规验人。先行动的僧侣仍可完成当夜保护，不因稍后死亡而倒撤已结算的行动。
- 可向死者核对生前已经得到但未记录的信息，不索要死后新查验。死亡触发、死后保留、假死、复活、重获能力按本局具体机制处理；不因公开死亡一律取消守鸦人等死亡触发。
- 死亡/复活与角色变化分时段重建；不能把当前角色倒套至先前死亡夜。标准暗流的最后常规行动夜仅给条件上界，不冒充实际收到过反馈。
- 表内死亡触发和持续效果是提醒位置，不等于延迟到那时才发生。失忆、获得能力等动态时序，以及DIY/未列/改写技能，不强行套默认表；本局明确夜序和裁定优先。

165项自动检查通过，包括首夜/其他夜晚分离、僧侣/小恶魔/占卜相对顺序、死亡夜晚/白天、复活、角色变化、死亡触发、DIY未知时序、最新追问窗口、每分支座位覆盖、范围合并和安全高亮。隔离浏览器验证了开始即进入流式报告、停止保留、后台完成不打断草稿、一次冲突核对与320/390像素排版。模型输出仍须对照原始信息核验；这些检查不声称是所有自定义机制的完整求解器。
