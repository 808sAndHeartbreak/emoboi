# v0.39 · 联合约束与条件推导

## 问题与目标

此前配额、声明和技能反馈分别存在，但配额经常只被当作最后的检查表；角色候选逐座位展开后，没有把新结论回代其他信息。结果是能锁定的身份仍被泛列为多种身份，后续也没有利用“某角色必在场”继续缩小恶魔范围。

本版增加通用结构约束层，不预设先盘外来者、圣徒或特定剧本。所有角色类型共同参与匹配；分支入口依据信息间的实际约束关系选择。目标仍是缩小当前恶魔范围，其次区分爪牙和关键失真来源。

## 输入与约束

`core.constraintAudit()` 生成两个互不混淆的模型：

- `hard`：在已覆盖的配置规则内，联合本人私有角色、明确公开能力交互、角色池、角色唯一性和起始类型配额。只描述结构可行性，不宣称已核验全部逐夜技能。
- `disclosure`：在当前阶段，自知且没有隐瞒限制或收益的善良玩家已经纠正挡刀、如实报身份。邪恶仍可假跳；酒鬼等不自知角色、疯狂、暴露风险和特殊获胜动机分别处理。全员有当前声明、至少第2天且没有明显待更正或标注冲突时，才标为可检验条件；这不是游戏硬规则。

声明数不等于实际类型数。自己采用私有角色，其余采用最新明确声明，并保留旧声明和改口。死亡不释放起始身份名额。角色变化、特殊配置和未覆盖的自定义机制交还原文路线分时点分析，不强套普通匹配结论。

每种合法配置都带有必在、排除的设置角色条件。最大流同时约束座位、唯一角色与各类型配额，残量图求每个位置真正可行的角色；必选角色通过下界锁定，不能靠一次贪心分配判断。可证明某角色必在、某人身份固定、某组恰有几名恶魔/爪牙时，将这些结论送入后续输入。

可选的角色必在性查询有35毫秒及96次查询预算；未完成不视为排除证明。相同事实缓存结果，事实、声明或规则改变后重算。原有异步准备阶段继续在分支间让出主线程。

## 推理与展示

共用推理要求改为：先传播约束、回代新身份与必在角色，再选择能有效缩小恶魔范围的未知量分支。信息来源的角色真假、是否如实报反馈、反馈是否受醉毒/误登记影响分开；认下角色不代表其每次反馈都有效。

二选一反馈统一支持洗衣妇、图书管理员和调查员。新的必在角色会连接相应反馈，登记例外、来源真假及具体夜次失能仍参与分析。修复“3、6两人”被误并为数字的情况、明确更正身份的识别和公开贞洁者触发文字的识别；相互矛盾的硬身份必须求交，不能由后来的宽条件覆盖。

原文路线和结构化路线都携带新约束。原文报告复核会检查是否漏掉能推出的新身份或必在角色；专项追问不强迫扩写整局。旧版本原文追问继续保留其对话，并更新新约束。

结构化报告仅在有合法输出帧和通过本地检查的相容代表方案时展示新的条件结论。依赖放宽报身份条件的反例保留，并明确所属前提；不因人工挑出的代表方案数量估算概率，也不把没有找到方案当作不可能。爪牙互换等无关差异仍合并，不展示配额检查过程和全员泛泛候选表。

## 验证及边界

新增13项回归，覆盖不同人数与剧本、自知与隐瞒例外、改口、冲突和缓存失效、旧对话升级，以及140组小问题与完全枚举逐位置候选对照。另有缩小角色池的机械案例：同一算法从公开交互和配额锁定镇民，并推出两个剩余位置恰含一恶魔、一爪牙，证明并非只针对外来者。

依据用户提供的报告TXT还原的12人案例，在当前完整报身份条件下可推出：8号圣徒、酒鬼必在、男爵不在场；随后连接图书管理员反馈，并保留间谍登记及来源异常分支。原始 `b01d3ca7` 请求JSON在指定位置未找到，此案例不冒充原始请求复现；未从TXT补造具体未明的洗衣妇所见角色。

完整钟楼测试335项、站点测试14项。没有本轮付费模型质量评测。本地完整世界检查仍限已覆盖的静态暗流范围；通用结构约束不等同全角色、全时序穷举，也不能保证模型一定不出错。
