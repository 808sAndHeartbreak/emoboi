# v0.30 · 恶魔优先与报告完成后展示

沿用共享约束与当前请求入口，保留原始记录和历史快照。当前流程为：记录编译 → 条件及数量剪枝 → 核验身份组合 → AI排序或专项查询 → 格式核对 → 一次展示报告。

## 推理与分类

- 善良视角优先收窄恶魔位置。标准静态暗流中，恶魔、爪牙和邪恶总数参与域传播，名额用尽时排除其他座位、名额只能由剩余座位满足时强制其类型。死者仍占起始名额，男爵在场必须占用爪牙名额。
- 细分条件使用明确的真实角色、正常反馈、酒鬼、邪恶假跳或其他善良假跳。真实身份不自动等于正常反馈；按夜限定不会扩大成整局正常。
- 每类先展示可由保守约束证明的恶魔范围。若所有邪恶候选已集中到不超过六位且明显小于全场的集合，直接说明该集合必含的恶魔与爪牙数量；不从已找到样例频率推导必然。
- 类内分开“不依赖中毒”和“需中毒解释”。前者可以有投毒者在场，只是不需要其使所采信信息失效。酒鬼、合法误登记和撒谎分别处理，不被统称为中毒。后者落实投毒者位置和作用夜次；同夜不能解释两个不同玩家同时吃毒。
- 已核验组合只差无关爪牙互换时合并，集中列出这些座位分摊的爪牙角色。恶魔位置、正常性、干扰项或有效投毒者位置有区别的组合仍保留；不把角色池的任意排列当成已验证组合。

## 进度与正文

传输仍使用流式接口，持续监测连接与保存已接收正文；界面不逐字渲染报告，不在流式阶段排序或重排分支。

- 本地计算：正在整理线索。
- 建立请求：正在连接。
- 已收到HTTP响应、尚无模型有效输出：等待模型响应。
- 收到思考内容：正在思考；仅使用者开启深度思考时流式显示该内容。
- 正文开始或格式复核：正在整理报告；思考区隐藏，最终正文核对后一次展示。
- 45秒无新有效输出：明确提示暂未收到新内容，可继续等待或停止重试。心跳和旧内容不伪造新输出；最终超时、断流、认证等仍显示对应错误。

不伪造进度百分比或无从得知的服务端状态。思考内容只在本次内存和界面存在，不进入报告、备份、对话上下文、错误详情或费用账目。支持返回记录、重开进度窗口和停止；停止或中断后已收到正文仍可保留为未完成内容。
